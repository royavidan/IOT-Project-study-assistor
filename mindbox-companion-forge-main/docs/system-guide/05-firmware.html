5. ארכיטקטורת הקושחה

5.1 שלוש משימות, שתי ליבות

משימה ליבה תפקיד פרטים
Arduino loop 1 UI + מכונת מצבים + חיישנים קלט → FSM → רינדור → פרסום טלמטריה; ‏watchdog ‏30s
"net" 0 כל ה-WiFi/HTTP ‏16KB stack; בקשה אחת לכל מעבר (שרשרת else-if); כל קריאות ‎WiFi.*‎ אך ורק כאן
"audio" 0 מיקרופון + רמקול ‏4KB stack, עדיפות 5; ‏RMS רץ ברציפות, צלילים מתור

שעון הסשן רץ על esp_timer תקופתי (10ms) — כך שגם אם ה-loop נתקע רגעית, הזמן לא מדלג.

5.2 חציית גבולות בין משימות — בלי race conditions

מנגנון מה עובר כיוון
mutex s_mux (Cloud) ‏TelemetrySnap (מדדים חיים) + CloudSettings (ה-downlink המפוענח) + תור שיעורי הבית דו-כיווני loop⇄net
xQueue s_cmdQueue (8) פקודות מרחוק (RemoteCmd: start/end/ring/message) net → loop
xQueue s_chimeQ (4) בקשות צליל loop → audio
recursive mutex (Storage) כל גישה ל-NVS (שתי הליבות כותבות) —
recursive mutex (UploadQueue) קבצי LittleFS של תור ההעלאה —

5.3 מכונת המצבים — 16 מצבים

State תפקיד
ST_BOOTING אתחול
ST_IDLE תפריט הבית; בודק לו"ז להתחלה אוטומטית, הודעות ממתינות, poll קונפיגורציה
ST_RUNNING סשן פעיל: דגימות, התראות, נוכחות, אימון אדפטיבי
ST_PAUSED מושהה; חזרה/סיום אוטומטיים לפי נוכחות
ST_COMPLETE סיכום 2 שניות → הצעת סבב / שיעורי בית / בית
ST_CYCLE_OFFER הצעת האינטרוול הבא (פומודורו רב-סבבים + הפסקה ארוכה)
ST_RESUME שחזור סשן שנקטע (checkpoint ב-NVS — שורד ניתוק חשמל)
ST_PAIRING קוד צימוד 6 ספרות; poll כל 3 שניות
ST_WIFI_SETUP סריקת רשתות + מקלדת מגע על המכשיר (או פורטל SoftAP מהטלפון)
ST_AGENDA מסך הלו"ז: היום + דפדוף 6 ימים קדימה (מהאתר)
ST_AUTOSTART ספלאש 10 שניות לפני התחלה אוטומטית של בלוק לימוד — נגיעה מבטלת
ST_MESSAGE הודעה/צלצול מרחוק מהאתר (30 שניות או נגיעה)
ST_HOMEWORK עדכון שיעורי בית מהיר אחרי סשן עבודה (נגיעה=+25%, ארוכה=סיום)
ST_DIAG מסך דיאגנוסטיקה חי (חיישנים + קודק)
ST_ERROR תקלת חיישן קריטית (באס I2C תקוע) — לא נכשל בשקט
ST_LOGGING (שמור; הכתיבה כיום סינכרונית)

5.4 עמידות לניתוקי חשמל ורשת

מנגנון איך
Checkpoint של סשן מצב הסשן נכתב ל-NVS; אחרי ניתוק חשמל המכשיר מציע "המשך או בטל" (ST_RESUME)
תור העלאות עמיד סשנים שהסתיימו בלי רשת נשמרים כקבצי JSON ב-LittleFS (עד 12); מועלים עם backoff מעריכי ‎5s→5m; חותמות זמן של סשני-offline מתוקנות ברגע ש-NTP חוזר
הגדרות שרדו-poll ה-CloudSettings האחרון נשאר ב-RAM; כשל poll לא מאפס כלום (השרת אף מחזיר 500 במקום ברירות-מחדל אם קריאת DB נכשלה)
Watchdog ‏Task WDT ‏30s עם panic — ריסטארט נקי במקום תקיעה; סיבת האיפוס האחרונה מוצגת על מסך ה-boot

5.5 מפת מודולים (src/, מבנה שטוח)

MindBox.ino סדר boot + לולאה ראשית + breadcrumbs Cloud.* / Payload.* משימת רשת, HTTP, ‏NTP; סריאליזציית סשנים
config.h / types.h SSOT פינים/דגלים/קבועים; מבנים ו-enums Sensors.* / Audio.* חיישני סביבה + ToF; קודק I2S מיקרופון/רמקול
StateMachine.* / Session.* ה-FSM; שעון סשן + דגימות + FLE Sound.* / Haptics.* צלילי אירועים (chimeMask); רטט (כבוי ב-S3)
Display.* / TimerScreen.* / Panel.* API רינדור; מסך הטיימר; התקן LovyanGFX Storage.* / UploadQueue.* NVS; תור LittleFS
Inputs.* / Touch.* / Keyboard.* מיזוג אנקודר+כפתור+מגע; דרייבר FT6336; מקלדת מגע Menu.* / Theme.* / Diagnostics.* עץ תפריטים; ערכות צבע; קונסולת serial

5.6 סדר ה-Boot (כל שלב מודפס למסך ול-Serial)

Storage(NVS) → Audio (soft-I2C codec BEFORE display claims the bus) → Display
→ reset-reason on screen (1.2s) → Inputs/Touch (calibration if needed) → Sensors (Wire+ToF)
→ UploadQueue (LittleFS) → Cloud (net task on core 0) → StateMachine → selfTest → WDT armed

הסדר אינו שרירותי: הקודק חייב להיות מתוכנת לפני שה-LovyanGFX תופס את פיני ה-I2C; המסך חייב לפני החיישנים כדי שתקלת חיישן תוצג; ה-selfTest רץ אחרון כשהכול למעלה.
